# Загрузка аккаунта Pyla по тегу

## Цель

Пользователь вводит тег Brawl Stars и получает профиль и своих бойцов без регистрации разработчика. Публичная программа не содержит SSH-данных, ключа Supercell или иных серверных секретов. Пользователь уточнил: защитить нужно доступ к самому VPS, загрузка данных может быть публичной.

## Проверенные факты

- Актуальным источником приложения служит default branch GitHub `Biomistik-Official/PylaAI-Biomistik-Realese`; локальная рабочая папка содержит старые и несвязанные изменения.
- В актуальных `webui/player_api.py` и `common/utils.py` профиль загружается через официальный API с токеном либо учётными данными портала разработчика.
- SSH-алиас `vgs` доступен. В `/root/pay tg bot/.env` есть `BRAWL_STARS_API_TOKEN`. Один проверочный запрос профиля с VPS вернул HTTP 200 с ожидаемыми полями. Значение ключа не выводилось.
- На VPS уже работает nginx с HTTPS. Существующие сайты и проекты должны продолжить работу.

## Рассмотренные подходы

1. Встроить общий ключ в приложение: исключено, поскольку пользователь публичного клиента сможет извлечь его.
2. Выдавать отдельный допуск каждому пользователю: добавляет регистрацию и не нужен для заявленной защиты самого VPS.
3. Отдельный публичный HTTPS API профилей: предлагаемый вариант. Адрес известен пользователям; права ограничены чтением публичного профиля по тегу.

## Предлагаемая реализация

- Отдельный серверный сервис под непривилегированным системным пользователем; отдельный каталог и systemd unit. Приложение слушает только loopback за nginx.
- Вход: один фиксированный GET endpoint с нормализованным тегом. Произвольные URL, команды, пути файлов, настройки и администрирование через него недоступны.
- Ключ копируется на самом VPS в отдельный защищённый файл для сервиса, без выдачи доступа к конфигурации VGS Money. Существующий файл и ключ VGS Money не изменяются. Отдельный ключ Pyla в будущем позволит независимо управлять квотой и отзывом.
- Фиксированный upstream `api.brawlstars.com`, проверка TLS, запрет перенаправлений, таймаут и ограничение размера ответа. Клиентам возвращаются только разрешённые поля профиля; секреты, upstream-заголовки и внутренние ошибки не возвращаются.
- Кэш профилей на несколько минут с ограниченным размером; лимиты по IP, общий предел upstream-запросов и ограничение параллелизма. Прокси-заголовки доверяются только локальному nginx.
- HTTPS endpoint добавляется отдельно от существующей панели. Служба ограничена средствами systemd и не получает домашний каталог root, SSH-ключи или доступ к другим проектам. Существующие правила SSH и сайты не ослабляются.
- Изменения клиента делаются от свежей версии GitHub в отдельном чистом checkout. Поле тега использует relay; ручной API остаётся дополнительным режимом. Автоматические обновления игровых данных также используют выбранный источник.
- Публикуется только клиент и несекретные исходники/инструкции. Серверные конфиги с ключами и рабочие данные в Git не попадают.

## Проверка результата

Тесты нормализации тегов, недопустимых маршрутов/методов, разрешённых полей, кэша, лимитов и upstream-ошибок. Проверка отсутствия секрета в клиентских файлах и ответах. Проверочный HTTPS-запрос из Windows по тегу без токена, отказ на посторонние маршруты, проверка изоляции процесса и сохранения доступности существующего сайта. Соразмерная регрессия актуального клиента. Перед публикацией — code review и проверка диффа на секреты.

## Ограничения

Публичный endpoint можно вызывать и вне Pyla; отличить произвольный скрипт от открытого клиента надёжно нельзя. Это не предоставляет административный доступ к VPS, но требует лимитов нагрузки. Абсолютная гарантия отсутствия уязвимостей не заявляется. Общий ключ делит upstream-квоту с VGS Money, поэтому relay должен строго ограничивать запросы. При недоступности relay интерфейс показывает понятную ошибку и сохраняет уже загруженные данные.
